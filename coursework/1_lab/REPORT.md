# Отчёты и проверка лабораторных работ №1–3

Исходные данные хранятся в модели `practice03` из [ПР №3](../pr3/README.md). Для демонстрации загружены 104 синтетические карточки студентов, 4 группы, 8 предметов и 192 события расписания. [C4 и DFD](ARCHITECTURE.md).

## ЛР №1. Десять студентов с минимальной посещаемостью

1. Elasticsearch ищет слово или фразу в названиях и текстах материалов. Для фразы `multi_match` типа `phrase` проверяет порядок токенов с учётом русского анализатора. Из совпадений извлекаются уникальные ID лекций.
2. Neo4j выбирает завершённые лекции за указанный период и студентов групп. Несколько совпавших материалов одной темы учитываются как одна тема.
3. PostgreSQL сверяет граф с реляционными данными и читает отметки по неделям. Доля равна `100 × посещено / ожидалось`. Сортировка идёт по точной доле, зачётке и ID. Отсутствие строки для ожидаемого завершённого занятия даёт HTTP 409.
4. Redis возвращает полные карточки выбранных студентов.

При запросе `целостность` за `2026-09-07…2026-12-27` Elasticsearch вернул 18 материалов по 9 темам. Neo4j отобрал 7 завершённых лекций и 104 студентов из 4 групп. PostgreSQL сформировал рейтинг из 10 строк, Redis вернул 10 карточек. Итоговый статус — HTTP 200. У первой зачётки `26Д0026` посещено 0 из 2. Для фразы `реляционная модель` получено 10 строк, для `модель реляционная` — 0. [Пример JSON](report.json).

## ЛР №2. Вместимость и оборудование для занятия

1. PostgreSQL выбирает полную карточку предмета по коду, семестру и начальному году учебного года. Семестр считается с начала программы. Семестр 7 соответствует 4-му курсу, а учебный год 2026/2027 — году набора 2023.
2. Из вложенного каталога MongoDB извлекаются технические требования для занятий предмета. По PostgreSQL проверяется состав оснащённых занятий и возвращаются полные карточки.
3. Neo4j идёт от курса и лекции к расписанию, нужным группам и активным студентам, которые зачислены к дате занятия. Количество уникальных студентов задаёт минимальную вместимость. Строки расписания одной темы с одинаковыми датой, временем, аудиторией и преподавателем считаются общим событием. Отменённые строки исключаются.

Для `demo_storage`, семестра 7, курса 4 и учебного года 2026/2027 PostgreSQL вернул один предмет. В его документе MongoDB отмечены три темы с оборудованием. Neo4j нашёл восемь событий по этим темам. Итоговый статус — HTTP 200. Для лекции 8 сентября в 10:45 в А-101 четыре группы, 102 слушателя, проектор и экран. Для отдельных занятий в компьютерных классах от 25 до 26 слушателей. Все 8 значений вместимости совпали с независимым реляционным запросом. Несогласованный семестр и курс дали 422, неизвестный предмет — 404.

## ЛР №3. Плановые и посещённые часы по группе

1. PostgreSQL возвращает полную карточку группы. В Neo4j выбираются назначенные группе курсы и расписание. В план входят лекции с точным тегом `специальная-дисциплина` на курсах выпускающей кафедры, включая запланированные. Отменённые занятия и лекции до зачисления студента из плана исключаются.
2. PostgreSQL получает отметки завершённых лекций по их ID и понедельникам соответствующих недель. Посещение учитывается при `is_present=true`. Для завершённой лекции без ожидаемой отметки отчёт возвращает 409.
3. Redis возвращает карточки студентов. Для каждой пары «студент — назначенный группе курс» считаются два показателя по два академических часа за лекцию. Курс без подходящих лекций остаётся в выдаче с нулевыми значениями. Состояние берётся из текущего расписания и журнала.

Для `ДЕМО-11-26` Neo4j вернул 46 событий без отмен, включая 6 лекций с нужным тегом. Три из этих лекций завершились в одну учебную неделю. PostgreSQL вернул 78 отметок по ним, из которых 65 подтверждают присутствие. Redis вернул 26 карточек студентов. Итог — HTTP 200 и 156 строк, по 6 предметов на каждого студента. Для зачётки `26Д0001` по `demo_arch` получено 4 часа плана и 2 посещённых. Независимый расчёт в PostgreSQL совпал по всем 156 строкам. Неизвестная группа дала 404.

## Проверка стенда

ПР №1 и пять CRUD-скриптов ПР №2 успешно выполнены в отдельном наборе контейнеров. Для лабораторных выполнен запуск на существующем наборе и отдельно с пустыми томами. Контрольные запросы ко всем трём отчётам вернули HTTP 200. При обращении к каждому отчёту без JWT получен 401. При удалении одной ожидаемой отметки в тестовом наборе ЛР №1 и №3 вернули 409. Swagger показывает четыре операции, включая вход. Двадцать два автоматических теста прошли.

## Сохранённые замеры SQL для ЛР №1

[sql/report.sql](sql/report.sql) идентичен [bench/optimized.sql](bench/optimized.sql).
Один индексный поиск отметок на занятие (`LATERAL + OFFSET 0`,
`MATERIALIZED actual_marks`), объединение ожиданий и отметок через `UNION ALL`
и одна агрегация устраняют повторный расчёт агрегата на каждого студента.
Недельный запрос исполняет 1/16 партиций, семестровый — 16/16.

Сохранённый SQL-прогон: PostgreSQL 16.15 ARM64, seed 0.42, три размера,
два прогрева и пять измерений с чередованием запросов. Схема/индексы ПР3,
`work_mem` и настройки планировщика не менялись. Все девять сценариев дали
одинаковый JSON baseline/optimized при обоих режимах внутренней трассировки;
контрольная фикстура прошла 12 проверок. Сам SQL после упрощения публичного
API не изменялся, поэтому результаты замера применимы к текущему запросу.
