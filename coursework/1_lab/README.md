# Учебная аналитика по ПР №3 и ЛР №1–3

Запусти Docker и выполни из каталога `coursework/`:

```bash
./1_lab/scripts/start.sh
```

Открой [Swagger](http://127.0.0.1:8000/docs), нажми **Authorize** и войди как `admin` с паролем из `1_lab/secrets/demo-credentials.txt`. Поля `client_id` и `client_secret` оставь пустыми. Подготовка Python и альтернативный порт описаны в [инструкции по запуску](../README.md).

| Что открыть в Swagger | Данные для проверки | Результат на демо-наборе |
| --- | --- | --- |
| **ЛР №1** · `GET /api/v1/reports/attendance` | `term=целостность`, `date_from=2026-09-07`, `date_to=2026-12-27` | 10 студентов, первая зачётка `26Д0026`, 0 из 2 лекций |
| **ЛР №2** · `GET /api/v1/reports/classroom-capacity` | `course_code=demo_storage`, `semester=7`, `study_year=4`, `academic_year=2026` | 8 событий, включая общую лекцию для 102 слушателей с проектором и экраном |
| **ЛР №3** · `GET /api/v1/reports/group-lecture-hours` | `group_code=ДЕМО-11-26` | 26 студентов × 6 предметов, 156 строк |

`POST /auth/token` обслуживает вход. В Swagger показаны только вход и три отчёта. Для повторной проверки этих запросов с уже поднятым стендом выполни `cd 1_lab && .venv/bin/python scripts/setup.py --check`.

Стенд автоматически загружает синтетические данные в модель `practice03` из отчёта ПР №3. При обновлении существующего демо-набора добавляются требования и теги, затем пересобираются проекции. Расписание и отметки сохраняются. Команда `./1_lab/scripts/stop.sh` останавливает стенд с сохранением томов.

Развёртывание ПР №1 и CRUD-упражнения ПР №2 хранятся в корне курса. Модель для текущих отчётов описана в [ПР №3](../pr3/README.md). Все три отчёта используют Compose из этого каталога.
